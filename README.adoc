= OpenShift 102 Workshop

The source of the OpenShift 102 Workshop site: four hands-on workshops (Helm, advanced deployment, Istio service mesh and Prometheus queries) for people who know the basics of Kubernetes and OpenShift, published together as one site and one PDF.

The site is https://redhat-na-ssa.github.io/openshift-102-workshop/[redhat-na-ssa.github.io/openshift-102-workshop].
Its xref:content/modules/ROOT/pages/instructor.adoc[Workshop instructor] page is the facilitator guide: what the workshops cover, the environment and requirements, before the day, and delivery notes.

This README is for maintainers of the repo.

== Layout

The repo is one Antora component made of a home part and nested workshops:

[cols="1,3",options="header"]
|===
|Folder |What it holds

|`content/`
|The home part: the Workshop home, Workshop instructor and Workshop attendee pages, the Shared CLI tools page and its snippet (`modules/ROOT/partials/cli-tools-container.adoc`), and the site's title, navigation and attributes in `content/antora.yml`.
`content/lib/dev-mode.js` is an Antora extension that adds a page listing the site and component attributes and puts pages missing from the navigation under *Dev Mode*; turn it on in `default-site.yml` while debugging.

|`workshops/helm/`
|The Helm Workshop: its pages in `modules/helm/pages`, and its navigation in `modules/helm/nav.adoc`.

|`workshops/deploy/`
|The Advanced Deployment Workshop: its pages in `modules/deploy/pages`, its navigation in `modules/deploy/nav.adoc`, and the read-only attendee RBAC its setup requirements apply, in `provisioning/attendee-rbac.yaml`.

|`workshops/istio/`
|The Istio Service Mesh Workshop: its pages in `modules/istio/pages`, and its navigation in `modules/istio/nav.adoc`.
The Istio and Service Mesh versions its pages show are attributes in both `content/antora.yml` and `workshops/istio/antora.yml`; keep them the same.

|`workshops/prometheus/`
|The Prometheus Query Workshop: its pages in `modules/prometheus/pages`, and its navigation in `modules/prometheus/nav.adoc`.

|`tools/`
|`install.sh` adds `istioctl` to the release's tools image, and `extra-tools` lists it so the image's banner and check include it.
|===

Each workshop's own `antora.yml` is used only when it is built alone; in the full site, `content/antora.yml` supplies the title, navigation and attributes, so an attribute a workshop needs goes in both.
The workshop pages link to the Shared CLI tools page and include its snippet only when the `openshift-102-showroom` attribute is set, which only `content/antora.yml` does, so each workshop still builds alone.

The site's look (theme, CSS, tabs, copy buttons, footer), the PDF look, the release (images, Helm chart and offline bundle) and the Pages, Release and Check content workflows come from https://github.com/shpwrck/workshop-common[workshop-common], which the other workshop repos share; change them there.

== Preview

Clone https://github.com/shpwrck/workshop-common[workshop-common] next to this repository, and run this from this repository's folder to preview the whole site:

[source,bash]
----
../workshop-common/scripts/preview.sh --watch
----

It builds the site the way the Pages workflow does, serves it on http://localhost:8080/ and rebuilds it when you save a change.
It needs Node.js and Python 3.

To build one workshop on its own, as it must build before it joins the site:

[source,bash]
----
../workshop-common/scripts/preview.sh \
  --watch \
  --workshop helm
----

The *Shared CLI tools* page shows the tools image that the Pages and Release workflows pass in, with a fallback for local builds in `content/antora.yml` (`tools-image-basename` and `tools-image-tag`).
Point them at your registry when building disconnected documentation, for example:

[source,bash]
----
antora generate default-site.yml \
  --stacktrace \
  --attribute tools-image-basename=ghcr.io/myorg/openshift-102-workshop-tools \
  --attribute tools-image-tag=v1.0.4
----

Every pull request runs *Check content*, which holds the lines it changes to the formatting conventions and checks that the site, and each workshop on its own, builds without warnings or broken links, and *Test PDF Build*, which builds the release PDF from `default-pdf.yml`.
A merge to `main` publishes the site.

== Adding a Workshop

Run this from this repository's folder, with a short lowercase name and the workshop's title:

[source,bash]
----
../workshop-common/scripts/add-workshop.py \
  NAME \
  "Workshop Title"
----

It creates `workshops/NAME` from the workshop template and lists it in both playbooks, `content/antora.yml`, the home part's navigation, and the home, instructor and attendee pages.
Then write its pages, its setup requirements, and its row on the instructor page.

== Releases

Run the *Release* workflow from the Actions tab with the next version, such as `v1.1.0`, or push a tag of that name.
It publishes the PDF, the runtime and tools images, the Helm chart and an offline bundle; see "Releases" in https://github.com/shpwrck/workshop-common[workshop-common]'s README.
The tools image adds `istioctl` (`tools/install.sh`) to the shared tools; keep its `ISTIO_VERSION` on the Istio release the pages target, `istio_version` in `content/antora.yml`.
